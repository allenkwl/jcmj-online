# 立體牌 v2：兩套牌身＋立著的別家手牌（實驗中，遊戲還沒用）

2026-10-26 使用者：
- 「另外三家的手牌雖然玩家看不到，但應該是立起來的才對……橫著的直立和背對的直立」
- 「整套牌一起畫，除了現在的豬肝紅，再另外畫一組金黃色，可以在統一五國後，在最後要打最後一國改用金黃色牌……兩套牌都一樣要放發牌測試程式」
- 「直立的牌寬度太窄（左右兩家用的牌）」「金黃色的顏色不行，直接要求畫金屬材質」
- 「我看過再進遊戲」

預覽：`devtools/立體牌v0.3.html`（牌桌）、`devtools/發牌動畫v0.7.html`（發牌）。兩頁都注入 `devtools/立體牌/tiles-sets.js`。

## 檔案（`maroon/`、`gold/` 各一套，`.png` 原檔＋`.webp` 給遊戲讀）

| 檔名 | 內容 | 用在 |
|---|---|---|
| `faceV` `faceH` | 躺著、牌面朝上（直／橫） | 牌河、副露、寶牌指示牌 |
| `backV` `backH` | 躺著、牌背朝上（直／橫） | 暗槓、發牌動畫的牌牆 |
| `standV` | **立著、牌背朝我們** | 對家的手牌 |
| `standH` | **立著、側面朝我們**（象牙白一半朝左家），跟躺著的橫牌一樣寬 | 左家的手牌 |
| `standHR` | `standH` 左右翻過來 | 右家的手牌 |

產生：`python3 tools/build-tile-sets.py`（原圖在 `../原圖/v2/`）。

## 怎麼來的

- **豬肝紅**：躺著的 4 種沿用 `assets/tiles3d`（v1.95 定稿）；`standV`、`standH` 是 Codex 新畫的（`原圖/v2/stand-maroon-1.png`，附定稿 4 張當參考圖鎖材質）
- **左右兩家**：Codex 畫的側面只有 185 寬 → 使用者：「codex 畫的直立牌寬度太窄小，這樣的視角不對，不論蓋牌或是直立都該一樣寬」→
  整塊拉到 240（跟躺著的橫牌一樣寬）。中間我會錯意試過「背對直立轉 90°」，撤掉
  - 一列裡每往下一張前進的距離跟躺著時一樣，立著的比較高，下面那張蓋住上面那張的下半截（`tiles-sets.js` 的 data-edge）
- **金黃**：第一版是把豬肝紅轉色（色相、明暗重新對應）→ 使用者：「顏色不行，直接要求畫金屬材質」→
  每一張豬肝紅送給 Codex「只把豬肝紅那一層改畫成拋光的金屬金，形狀構圖不變」（`原圖/v2/gold-*.png`），
  再照不透明範圍裁切、縮成跟豬肝紅那張一樣大（`fit_to`）。左右兩家一樣用金的 `standV` 轉出來
- 共同一招（之前 v1.95 學到的）：Codex 抓不準比例，形狀一律以定稿那張為準，只讓它改材質
