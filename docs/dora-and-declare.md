# 祥瑞與宣戰

> 草案 2026-09-29。**尚未實作**，也還沒定案 —— 末節「待拍板」有四個問題要先回答。
> 規則底盤：日本麻將（十三張），同 `net-turn-model.md`。

這一份把兩個功能綁在一起寫，因為它們互相是對方存在的理由：

- **祥瑞**（日麻的寶牌／ドラ）給這一局隨機指定幾張「今天值錢的牌」，製造分數變異。
- **宣戰**（日麻的立直）讓聽牌的人公開宣告，換取翻開**裏祥瑞**的機會。

分開做的話，祥瑞少了最刺激的那一半，宣戰則要另外發明一個獎勵。綁在一起，
宣戰的獎勵就是現成的，而且好解釋：**「賭一把，翻開背面那張。」**

---

## 一、為什麼是這兩個，而不是全面對齊日麻

全面對齊要換掉和牌價值的整套模型，而那會連帶把七國技能一起拆掉：

| 現況 | 日麻 | 衝突 |
|---|---|---|
| 番種**單選最高**（`SPECIAL_HANDS` 照優先序找第一個） | 役**相加** | 不是換一張表，是換一套組合模型 |
| 技能**乘分數**（齊 ×0.7、楚 ×1.3、秦 ×1.5） | 點數是**查表整數**（8000／12000） | ×0.7 會算出 5600 這種不存在的點數；技能得全部改成「加飜」 |
| 任何牌型都能胡 | **無役不能和** | 「我聽牌、我摸到了、系統說不能胡」對新手最難解釋 |

祥瑞與宣戰是少數**不碰這三條**的功能：祥瑞是純加法，宣戰的獎勵掛在祥瑞上。

## 二、祥瑞

### 2.1 王牌區（**已經有了，而且大小剛好，不要動**）

> 訂正 2026-09-29：草案初稿寫「目前完全沒有王牌區、切出來會讓活牌山從 84 掉到 70、
> 一局少三巡」。**全錯。** `game-state.js:72` 就有 `DEAD_WALL = 14`，
> `createMatch` 已經設 `deadWallStart = wall.length - 14`，實測：
> `deadWallStart = 122`、活牌山 **70 張＝每家 17.5 巡**，跟日麻標準一致。
> 所以這不是前置工作，祥瑞可以直接用現成的王牌區。
> （使用者 2026-09-29：「若原本就有切，那就維持現狀吧」）

```
牌山 136 張（index 0..135）
├─ 0..51     起手發牌 13×4
├─ 52..121   活牌山 70 張＝每家 17.5 巡
└─ 122..135  王牌 14 張
   ├─ 122..131  指示牌 10 張 ＝ 5 組（表,裏）   ← 祥瑞要用的，目前空著沒人碰
   └─ 132..135  嶺上牌 4 張                      ← drawRinshan 從 wall 尾端往回取
```

**14 張剛好夠，一張不多一張不少**：5 組指示牌 ＝ 開局 1 張 ＋ 最多 4 次槓祥瑞，
正好對上 `MAX_KONGS = 4`。切到 8 張只剩 2 組，槓祥瑞最多 1 次。

位置不會打架：嶺上從 135 往回取（135→132），指示牌放低端（122→131）。
槓過之後 `deadWallStart--`（王牌從活牌山補回來，模擬真實牌桌），
四次槓完 `deadWallStart = 118`，指示牌的 122..131 仍然在王牌區內。

### 2.2 指示牌 → 祥瑞

開局翻開**一張**指示牌。真正的祥瑞是**指示牌的下一張**，不是指示牌本身
（這一層轉換是故意的，不讓人一眼看穿該留什麼）。

| 指示牌 | 祥瑞 |
|---|---|
| 1萬～8萬 | +1（3萬 → 4萬） |
| 9萬 | 1萬（繞回） |
| 筒、條同理 | |
| 東→南→西→北→東 | 繞回 |
| 白→發→中→白 | 繞回 |

**槓祥瑞**：每槓一次，立刻再翻一張指示牌，祥瑞多一種。
所以槓是雙面刃 —— 你加分，別人也吃得到新的那張。

### 2.3 計分：加法，而且在技能之後

日麻的寶牌是加飜（乘法）。這裡**不能**這樣做，會跟技能倍率疊乘爆掉。

```
最終分 = ceil( 基礎番種分 × 押注倍率 × 莊家加成 × 國家技能 ) + 祥瑞張數 × DORA_PTS
                └────────────── 現有的乘法鏈，完全不動 ──────────────┘   └── 新增 ──┘
```

- `DORA_PTS` 初值建議 **2 × POINT_SCALE = 20**（基本和牌 80 的四分之一）。
- 放在技能**之後**加，所以齊的「善守 ×0.7」不會把祥瑞也打折 ——
  祥瑞是「這張牌今天值錢」，跟你是哪一國無關。
- 祥瑞**不是役**：手上全是祥瑞也不能靠它和牌。這裡因為沒有無役不能和，
  這條實際上不會被觸發，但寫進規則說明裡，之後真的加役時語意才不會變。

### 2.4 赤祥瑞：**建議先不做**

紅 5 要動 `tools/build-*.py` 的牌面圖與 `assets/manifest.js`，
而它帶來的變異祥瑞本身已經提供了。留在「以後可能」。

## 三、宣戰

### 3.1 條件

| 條件 | 是否要求 | 理由 |
|---|---|---|
| 聽牌 | **要** | 宣戰的語意就是「我準備好了」 |
| 活牌山剩 ≥ 4 張 | **要** | 宣戰完一張都摸不到沒有意義 |
| 這一局還沒宣戰過 | **要** | 宣戰不可取消 |
| **門前清** | **不要求** | 見下 |

**為什麼不要求門清。** 日麻要求門清，是因為立直本身是個**門前役** ——
它存在的意義就是「讓門清手有役可以和」。這裡沒有無役不能和，那個功能不存在，
門清就只剩限制而沒有理由。而且技能鼓勵吃碰槓（鐵騎、護送），
門清手會很少，宣戰會變成大部分局都不會出現的功能。

**改成獎勵階**：誰都能宣戰；門清宣戰多一段加成（見 3.3）。

### 3.2 代價

1. **鎖手** —— 宣告之後摸到什麼打什麼，除非那張能胡。
   ⚠️ 這可以直接複用現成的「交給系統打」（`autoPlay`／`setAuto`），UI 幾乎不用新做。
2. **公開** —— 名牌上頭像左邊亮出宣戰章，四家都看得到（見第五節）。
3. **振聽升級** —— 宣戰後若放過一次榮和，**這一局內永久振聽**
   （現在的同巡振聽是「摸到下一張就解除」，宣戰後不解除）。
4. **不得槓** —— 宣戰後不能再槓。
   日麻有一套「只有不改變聽牌型、且摸到的就是那張才能暗槓」的細則，
   太瑣碎而且極少發生，直接禁掉比較好解釋。

**不做 1000 點供託。** 這遊戲沒有「點棒」這個概念，
為了立直硬引進一套場上共享的棒子，成本遠大於收益。

### 3.3 獎勵

```
宣戰加成 = 裏祥瑞（翻開指示牌底下那張，只有宣戰的和牌者看得到）
         + DECLARE_PTS                （固定加成）
         + DECLARE_MENZEN_PTS          （門清宣戰才有）
```

裏祥瑞就是那個「賭一把」。翻出來對到三張，這一手直接翻身 —— 這是宣戰的全部樂趣來源。

### 3.4 一発：**第二期再說**

宣戰後的第一巡內和牌加成。實作不難（一個旗標，任何人鳴牌或自己摸到下一張就清掉），
但它會讓「這一巡算不算數」的邊界變多。先不做，把第一期的表面積壓小。

## 四、資料與流程

### 4.1 狀態（`game-state.js`）

```js
hand.wall          // 活牌山（現有，長度 84 → 70）
hand.deadWall      // 王牌 14 張                         ← 新增
hand.doraShown     // 已翻開的指示牌陣列（開局 1 張，每槓 +1）← 新增
hand.uraShown      // 對應的裏指示牌陣列（不公開）        ← 新增
hand.seats[i].declared      // null | { turn, menzen }   ← 新增
hand.seats[i].furitenLocked // 宣戰後放過榮和 → 永久振聽 ← 新增
```

### 4.2 流程（`flow.js`）

| 時機 | 做什麼 |
|---|---|
| 開局發牌後 | 從王牌翻第一張指示牌，`ev('dora', …)` |
| 槓成立、補嶺上牌之後 | 再翻一張指示牌，`ev('dora', …)` |
| 玩家宣戰 | 驗條件 → 記 `declared` → `ev('declare', { seat })` → 這一家進入鎖手 |
| 和牌結算 | 數祥瑞；若和牌者 `declared`，一併翻 `uraShown` 並計入 |
| 流局 | 不翻裏祥瑞 |

### 4.3 計分（`scoring.js`）

`handValue()` 末端加一段，**在現有乘法鏈之後**：

```js
total = ceil(base × bet × dealer × skill);       // 現有，不動
total += countDora(winTiles, doraList) * DORA_PTS;
if (seat.declared) {
  total += countDora(winTiles, uraList) * DORA_PTS;
  total += DECLARE_PTS + (seat.declared.menzen ? DECLARE_MENZEN_PTS : 0);
}
```

⚠️ 數祥瑞要數**整手牌**：手牌 + 副露 + 和的那張。副露裡的祥瑞照算。

### 4.4 宣告仲裁（`claim-arbiter.js`）

- 榮和判定要看 `furitenLocked`
- 宣戰後那一家的「吃碰槓」一律回不能（鎖手）

## 五、連線

這是宣戰最大的價值：**它讓「誰聽牌」變成一個公開事件，四台必然一致。**

| 資料 | 放哪 | 誰看得到 |
|---|---|---|
| `doraShown`（指示牌） | `/states`（公開狀態） | 所有人 |
| `uraShown`（裏指示牌） | `/secret`（只有群主） | 群主；和牌結算時才隨結果廣播 |
| 宣戰事件 | 群主廣播的 `ev('declare')` | 所有人 |

⚠️ **裏指示牌絕對不能進 `/states`。** `/states` 是全體訂閱的，
放進去等於開 devtools 就看得到 —— 這跟手牌走 `/hands/{uid}` 是同一條理由。

宣戰本身走現有的「用戶端送動作 → 群主驗 → 廣播」那條路（`net-turn-model.md` 第三節），
不需要新的通道。

## 六、AI

### 6.1 何時宣戰

`ai.js` 現在是向聽數導向。宣戰要多一個判斷，建議的簡單策略（可調）：

- 聽牌 + 活牌山剩 ≥ 8 張 → 宣戰
- 已經有人宣戰、而自己的聽牌很差（剩張少）→ 不宣戰，轉防守

⚠️ **不准用 `Math.random`**（`ai.js` 的硬性約束）：線上版要能重放，
同一份狀態每台算出來的下一步必須一樣。

### 6.2 被宣戰之後怎麼防守

現在的危險度是用「現物 + 筋 + 副露推測」估的。有人宣戰之後，
「這一家聽牌」從推測變成**確定**，威脅度應該直接拉到最高。
這是現有 `threat` 那一項的輸入變更，不是新機制。

> 補記 2026-09-29：先前誤以為 AI 會偷看手牌。**不會。** `visibleCount()` 只在
> `i === viewerSeat` 時數自己的手牌；`test/ai.test.js` 有一組測試把別家手牌整個
> 換掉、要求 AI 決定完全不變，71 項全過。所以宣戰對人、對電腦的代價都是真的。

## 九之二、製作上的地雷（2026-09-29 對著程式碼查過）

依嚴重度排序。**前兩顆一定要在動工前處理。**

### ⚠️ 一、偏向發牌會伸手進王牌區，會讓祥瑞產生反向偏差

`deal-seed.js` 的 `placeHand()` 找「玩家想要的那張牌」時，搜尋範圍是整個牌山：

```js
for (let w = DEALT; w < wall.length; w++) {      // ← DEALT=52，上限是整副牌尾
  if (wall[w].display === want) { found = w; break; }
}
```

**包含王牌那 14 張。** 今天完全無害 —— 王牌只拿來當嶺上牌，哪一張都一樣。
但指示牌一放進去就不同了：偏向發牌會把被照顧那位**不要的牌**換進王牌，
於是指示牌會系統性地偏向「那個人手上沒有的牌」——
**被偏向照顧的玩家，反而比較不容易吃到祥瑞。**

這種偏差看不出來也測不到（除非專門去測），而且方向跟直覺相反。

**修法**：搜尋上限改成 `wall.length - S.DEAD_WALL`。一行，但要配一支測試
釘住「偏向發牌永遠不碰王牌區」。**這件事跟祥瑞無關也該做** —— 偏向發牌本來就
不應該動到王牌。

### ⚠️ 二、`netPublicState` 是「刪黑名單」，新欄位預設外流

```js
function netPublicState(r, gameId) {
  const pub = JSON.parse(JSON.stringify(match));
  delete pub.seed;
  pub.hand.wall = [];
  pub.hand.seats.forEach(st => { st.handCount = st.hand.length; st.hand = []; st.furitenTemp = false; });
```

它是**逐項刪掉**不該公開的東西，不是**逐項挑出**可以公開的東西。
所以只要在 `hand` 上新增一個欄位、忘了在這裡補一行 delete，它就會進 `/states` ——
而 `/states` 是全體訂閱的，開 devtools 就看得到。

**所以裏祥瑞絕對不能存成 `hand` 的欄位。**

**建議：裏祥瑞不要存，和牌結算時由群主從 `wall` 現算。**
`pub.hand.wall = []` 已經把牌山清掉，用戶端在結構上就拿不到，
不存在「忘記加一行」這個失敗模式。表祥瑞則相反 —— 它本來就公開，
存成已翻開的**牌物件陣列**（不是位置索引，因為用戶端沒有 wall 可以解析）。

### 三、宣戰的「鎖手」必須做在規則層，UI 複用只是順便

初稿寫「可以直接複用現成的『交給系統打』」—— **那只對畫面成立。**
`autoPlay` 是主 HTML 裡的變數，別台不認得，群主也不會因此擋下你的動作。

真正的限制要做在兩個地方：

- `flow.turnOptions()` —— 宣戰後只剩「打出剛摸到的那張」與「自摸」
- `claim-arbiter` —— 宣戰後吃／碰／槓一律回不能

UI 那邊複用自動打牌仍然省事，但它是**表現**，不是規則。

### 四、宣戰是新的動作型別

`flow.submit()` 目前只認 `'claim'` 與打牌。要加 `{ type: 'declare', seat }`，
並在 `turnOptions` 裡吐出「可不可以宣戰」。
線上走現有的「用戶端送動作 → 群主驗 → 廣播」那條路（`net-turn-model.md` 第三節），
**不需要新的資料通道**。

### 五、永久振聽要存新欄位，而且不能公開

現在只有同巡振聽 `furitenTemp` 是存下來的；永久振聽是 `R.isFuriten()`
從 `discards` **現推**的。宣戰後「放過一次榮和就這一局都不能胡」推不出來，
必須存。

⚠️ 而且 `netPublicState` 目前會把 `furitenTemp` 清成 false —— 那是刻意的，
別人不該知道你剛剛放過。新旗標同理：**宣戰本身是公開的，但「他剛剛放過一次」不是**，
所以新旗標也要一起清掉（又一次踩到地雷二）。

### 六、（已確認沒問題）技能換牌不會動到指示牌

`swapWithWallTail()` 是唯一會改寫 `wall` 內容的函式，它取的是
`deadWallStart - 1`（活牌山最末張），永遠在活牌山裡，碰不到 122..131 的指示牌。
四次槓之後 `deadWallStart = 118`，它寫的是 117，仍然安全。

## 十、待拍板
