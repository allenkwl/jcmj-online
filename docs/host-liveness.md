# 開桌的人與玩家「在不在」：同帳號回座、久久不動、開桌的人跳背景

> 2026-10-24 討論中（使用者回報：手機開桌、離開後換電腦（同一帳號）回來，另一位真人在桌上，整桌卡住）。
> **v1.93 實作**（2026-10-24）。定案見第二節；避免兩台同時當開桌的人見第三、六節（最後採用第六節：用現有的「帳號正在哪一桌」判斷是哪一台）。

## 一、問題

1. **同帳號回來被當成新人**：認人靠帳號（uid）不靠裝置。電腦用同一帳號從大廳加入進行中的桌 → 以「待入座」加入，
   成員名單又出現開桌的 uid → 別台以為開桌的人回來了、不接手；電腦又不跑牌局 → 整桌停住。
   已經換人接手的話，電腦進來會讓那個座位 endSub、改等一個不出牌的人 → 一樣停住。
2. **輪到自己出牌沒有時限**：鳴牌 20 秒、占卜 15 秒都有，出牌沒有。久久不動（跳背景、離開座位）整桌就等。
3. **開桌的人跳背景**：在線判定只靠 onDisconnect（net.js 開頭的說明：心跳因為誤判與流量拿掉了）。
   手機跳背景時連線常常還在 → 名單上還有他，但他的程式停了 → 整桌停住。

## 二、定案

| # | 問題 | 定案 |
|---|---|---|
| 1 | 同帳號回來 | **直接回到自己的座位**（不問、不當待入座）；原本是開桌的人而且還沒人接手 → 讀 /secret 接著當開桌的人 |
| 2 | 保險 | 待入座（pending）的成員**不算**座位上的人在場 |
| 3 | 出牌時限 | **30 秒**，最後 10 秒才顯示；**畫面中央**寫「N 秒後由 ○○（武將）代打」，秒數自動倒數 |
| 4 | 久久不動被代打，戰果算不算 | **不是斷線就照常記**；但如果**一直在背景到新的一輪開始**，比照斷線（這一場不記） |
| 5 | 開桌的人在背景多久換人 | **10 秒**（跟斷線一樣） |
| 6 | 開桌的人在背景時 | 頁面在背景**不回答**存活探測；別台發現「該動卻沒動」才去問一次，不回到每秒心跳 |
| 7 | 不能變成兩台開桌 | 見第三節 |

## 三、避免兩台同時當開桌的人（2026-10-24 討論後改：不加輪值編號、不改規則）

「誰是開桌的人」本身只會有一個：`groups/{群}/host` 用 transaction 搶，只有一台搶得到（現有）。
危險的是**舊的那台不知道自己已經被換掉**，醒來後照樣推流程、發布狀態。
不同帳號：規則只准現任開桌帳號寫，舊的寫不進去。**同一帳號**：規則分不出是哪一台。

做法：開桌的那台**自己判斷**還是不是開桌的人（使用者：不要輪值編號，怕太複雜）。

1. **記下是哪一台裝置**：`groups/{群}` 多一個 `hostDev`（每個分頁一個亂數）。同一帳號兩台的 uid 一樣，
   只比 host 分不出來 —— 這一個欄位是必要的，但只是「哪一台」，不是會一直加的編號。
   接手的 transaction 改成同時看 host＋hostDev（同帳號從手機換到電腦時，host 的值不變，只有 hostDev 變）
2. **跳背景就凍住、醒來先確認**：開桌的那台一進背景（visibilitychange → hidden）就凍住流程（不跑 flow、不發布）；
   回到前景時，**等連線恢復、從伺服器讀**（不能讀本機快取 —— 剛醒來的快取還寫著自己是開桌的人）
   `groups/{群}` 的 host＋hostDev：還是自己才解凍，否則退成一般玩家（netDemote）
3. **剩下的空窗：自己修好**。跳背景前已經送出、但連線其實已經斷了的那一筆，會在醒來重連時補送，
   可能把新開桌的人的狀態蓋掉一次。發布的狀態帶上 hostDev，新開桌的人監看 /states，
   看到不是自己發的就立刻重發一次 —— 最多閃一下

**不改 Firebase 規則**：規則是全站共用的，舊版頁面（還開著 v1.91 以前的人）寫入時不會帶新欄位，
規則一改，他們整桌當場寫不進去、卡死。上面 1～3 已經讓畫面不會錯，規則那一道換來的只是少閃一下，不值得冒這個險。

## 四、定案 4 的「新的一輪」

＝**下一局**開始（重新發牌、占卜）時他還在背景 → 比照斷線，這一場不記給他。

## 五、走一遍：同帳號手機換電腦（2026-10-24 使用者問「能 cover 到嗎」）

先更正：登入的帳號**有**一個 10 秒一次的「這個帳號正在哪一桌」紀錄（lobby.js 的 takeLock → Net.claimSession，
30 秒沒更新算過期）。它只用來**擋同一帳號第二台上桌**，不拿來判斷在不在場。

| 手機的狀態 | 電腦進得來嗎 | 照第三節的做法 |
|---|---|---|
| 真的關掉了（斷線） | 進得來 | ✅ 電腦回座；還沒人接手 → 電腦接著當開桌的人；已經有人接手 → 當一般玩家 |
| 在背景 **< 30 秒** | **擋下**：「你的帳號正在○○（另一台裝置）」 | ✅ 現有機制；等一下或回到手機 |
| 在背景 **> 30 秒**（紀錄過期，連線卻還在） | 進得來 | ⚠️ 只記「開桌的是哪一台」不夠，要補下面兩點 |

最後一種要補的：

1. **「哪一台」要記在每個座位，不只開桌的人**：電腦回座後，手機和電腦是同一個座位、同一個帳號，
   兩台都讀得到那副手牌、都能出牌。座位記下目前是哪一台（成員資料的 dev），手機醒來先確認，
   不是自己 → 不再出手，回大廳並說「這一桌已經在另一台裝置上繼續了」。
   醒來先確認對**每一台**都做（不只開桌的那台）：一般玩家的手機醒來時代打的計時器也可能先送出一手
2. **共用的成員節點會被手機刪掉**：同一帳號的成員節點是同一個（members/{uid}）。手機的連線之後真的斷掉時，
   伺服器會照手機當初掛的 onDisconnect 把節點刪掉 —— 刪掉的其實是電腦的 → 別台以為電腦走了，10 秒後開代打。
   電腦要監看自己的成員節點，在牌局中被刪掉就馬上補寫回去（跟網路瞬斷時的 _watchRejoin 同一套）；
   手機醒來發現被換掉時，先取消自己的 onDisconnect 再離開

## 六、改用現有的「帳號正在哪一桌」當判斷（2026-10-24 使用者：手機回前景也要被擋，畫面說「你的帳號正在某某桌」）

同一帳號兩台只會發生在**登入的帳號**（匿名身分綁在瀏覽器上，兩台的 uid 本來就不同），
而登入的帳號本來就有一筆 `players/{uid}/session = { tab, table, at }`，記著「現在是哪一個分頁在打」。
→ **「哪一台」直接用這筆的 tab**，第三節的 hostDev、第五節的座位 dev 都不用另外加。

- 醒來先確認（每一台都做）：從伺服器讀 session —— tab 是自己 → 照常；
  是別台、而且沒過期 → **跟電腦被擋時同一句**「你的帳號正在「○○」（另一台裝置）」，退出這一桌回大廳（先取消自己的 onDisconnect）
- 開桌的人：host 是自己的 uid **而且** session 是自己這個分頁，才算開桌的人
- ⚠️ 要改的地方：每 10 秒更新 session 現在是**直接覆寫**。手機醒來時這個計時器可能先跑，把電腦的紀錄蓋回手機 →
  改成 transaction：紀錄是自己的、或已經過期才寫；是別台的就不寫，改走上面的「被擋」
- 第五節第 2 點（共用成員節點被手機的 onDisconnect 刪掉 → 電腦補寫回去）照舊要做

## 七、實作（v1.93）

- `src/flow.js`：startSub 的 `idle`；markSubbed 跳過 idle；idleToGone（新的一局開始 → subbed）
- `src/net.js`：claimSession 改 transaction、不掛 onDisconnect；checkSession（伺服器讀）；pingMember＋pingGate（指定對象、在背景不回答）；
  joinGroup 的 rejoin；mySeatIn；_watchMyNode（成員節點被刪就補寫）；abandonGroup；readHostIdFresh；
  pushCmd 帶 gameId、watchCmds 的 replayMs（接手時補收 30 秒內這一場的出牌／鳴牌／回來）
- `src/lobby.js`：進行中的桌有我的座位 → doRejoin；10 秒一次的更新寫不進去 → superseded（跟被擋同一句）
- 主程式：netPresentIds（待入座不算在場）、出牌 30 秒＋中央倒數、'back' 指令、凍住／醒來確認、遞補問開桌的人、netResumeHost
- 測試：`test/idle.test.js`（規則層）、`test/e2e-liveness.test.js`（模擬器：久久不動、同帳號手機換電腦、開桌的人跳背景被接手）

實作中踩到的：
- 開桌的人**自己**被代打時，waiting 還寫著「輪到我」→ scheduleAuto 以為在等自己、武將不動 → 代打開始／結束後重算 waiting（netWaitingNow）
- 同一帳號的電腦會替手機回答「開桌的人在不在」→ 還沒真的接手當開桌的人就不回答（pingGate）
- 新開桌的人只收接手之後的指令 → 舊開桌那台凍住時收到的「過」丟了，視窗要等滿 20 秒 → 補收；
  但押注、地圖、續場確認補收回來會把等待重新打開（整桌停住）→ 只補收出牌／鳴牌／回來

## 八、四人坐滿的桌也能回座（v1.94）

大廳判斷「坐滿了」是數成員名單有幾筆。同一帳號換裝置時，手機只是在背景、它那一筆還在 →
四位真人的桌算起來 4 筆，那一列原本點不下去 → 回不了座。
改成：進行中、坐滿了也能點，點下去查這一場有沒有我的座位（mySeatIn）—— 有就回座，沒有才說「這一桌已經坐滿四位主公了」。

測試踩到的（不是程式錯）：e2e 裡的玩家不會按鳴牌視窗，那張牌他吃得到時視窗要等滿 20 秒逾時，
「牌局照常往前」偶爾等不到 → 測試頁面看到鳴牌視窗就按「過」。
