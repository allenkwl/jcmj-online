# 連線：七國進度與國庫（2026-10-16 與使用者定案；第一階段 v1.68 完成）

取代 `docs/online-campaign.md` 的「一桌一段戰役」。舊文件留著當歷史紀錄。

## 一、起因與決定

2026-10-15～16 討論（使用者原話節錄）：

- 「等等把國庫邏輯也加入連線模式」
- 「國庫變負數亡國的玩家會被踢出牌局（機率很低沒關係）」
- 「已經有人在玩的牌局是不是開放讓人加入？被踢出的或是斷的人都有機會回牌桌」→ 決定：**可以加入，下一場入座**
- 亡國的人回同一桌：**當新人**
- 「連線和單機分開吧」
- 「希望能帶著已統一的國家加入牌局」→ 進度**跟著人走，不跟著牌桌**
- 「要加入牌桌（不論全新桌或是進行中的）一樣要選國家，若選到的國家是自己之前打過沒有統一天下的，就把進度帶進來，
  所以每個玩家就會有七組進度……若選不到也可挑其他玩家沒選的重新來（當然之後也會記錄下來）」
- 統一天下之後再選那一國：**重新開始**（統一紀錄留在功業簿）
- 亡國：**那一國的進度刪掉**（「不會有人想留」）
- 舊的連線存檔：**清掉重來**
- 「同一個玩家只能一個身份上線」→ 同一個瀏覽器只能在一桌
- 跨裝置帶進度：匿名登入認不出「同一個人」→ 使用者：「只記瀏覽器不太好」→ **加選用的登入**（Google＋信箱連結，見第十一節）
- 缺席的人**不保留座位**（「不用保留位子」）
- 「可以互相看得到國庫，但要考慮怎麼顯示」

## 二、資料：每個玩家七份進度，一國一份

沒登入：存在玩家自己的瀏覽器（localStorage）。登入之後：存在 Firebase，瀏覽器裡留一份快取（第十一節）。
資料格式一開始就照雲端的樣子寫，之後不用再搬一次。

```
jcmj_online_kingdoms = {
  qin:  { kingdom:'qin', conquered:['han','wei'], gold:2450, matches:8, lastStreak:0, boost:false,
          minLevel:2, updatedAt },
  zhao: …,          // 沒出征過的國：沒有這一筆
}
jcmj_online_lock = { kingdom, table, at }      // 「同一個瀏覽器只能在一桌」用，見第六節
```

- 欄位跟單機的戰役進度（`campaign.js` 的 player）同一套：征服地、國庫、場數、連敗、追趕機制
- **統一天下** → 記進功業簿（標 🌐 連線、附國庫與同桌名字），那一國的進度**刪掉**，再選就從頭開始
- **亡國** → 那一國的進度**刪掉**
- 單機的七國戰役與這七份**完全分開**

## 三、加入牌桌

1. 大廳列出所有牌桌：等待中的、**進行中的**都列，寫「進行中・第 N 局・空 1 位」；坐滿四位真人的不能加入
2. 按加入 → **擇國而立**：
   - 每一國的卡片顯示**自己的進度**：「秦：征服 3 國・國庫 2,450 兩・第 8 場」／「趙：尚未出征」
   - 同桌已經有人選的國**變灰**
   - 「使用中」：自己在另一桌正用著的那一國（見第六節）
3. 選了有進度的國 → 帶進來；沒有進度 → 從頭開始（2000 兩、只有本國）
4. **等待中的牌桌**：開打時入座。**進行中的牌桌**：等這一場打完，下一場開打時入座；在那之前那個座位照樣由電腦武將打
5. 同桌**本國不會重複**（擇國時就擋掉），征服地可以重複（各自的收藏，本來就允許）

## 四、名冊的意義變了

- 以前：名冊記「這一段戰役的成員」，缺席的人座位保留、由他那一國的武將代打
- 以後：牌桌只是**房間**。在房間裡的人上桌；空位由電腦補（電腦用沒人選的國）
- 缺席的人**不保留座位與本國**（2026-10-16 定案）—— 進度已經跟著人走，他可以帶同一國去任何一桌

## 五、國庫與押注（跟單機同一套）

- 本錢 **2000 兩**，每征服一國戰利品 **300 兩**，每一場的輸贏進出國庫
- 押金：押特殊牌型 **80**、孤注一擲 **160**；國庫不夠付的選項變灰，「普通胡牌」永遠能選
- 做成特殊牌型胡牌才乘倍率、押金退回；沒做成進彩池（v1.61 起連線已經是這套）
- **v1.76 實作**（2026-10-17 使用者定案：舊進度的國庫**維持 2000、不補算**戰利品；結算框讓大家看到誰亡國；亡國後回大廳）：
  - 每個人的國庫快照跟著座位（`match.seats[i].gold`，開打時從成員資料的 camp 來）走進公開狀態，
    每台用 `OC.settleGold` 算出所有主公的「前 → 後」（輸入全公開，四台一樣）；自己的底數以本機進度為準
  - 亡國的人一結算就自動回答「離開」（別人不用等他看完動畫）；開桌的人亡國照樣等大家決定、交棒後才走
  - Firebase 規則不用改（沒有新欄位要驗證；亡國走原本的「離開」）
- **一場結算時國庫 < 0 → 亡國**：
  - 亡國的人播亡國動畫 → 按「確定」→ 回大廳；那一國的進度刪掉
  - 他離開這一桌（視同退出），座位空出；其他人照常打下一場
  - 他可以再加入（同一桌或別桌），選國照第三節

## 六、同一個玩家只能在一桌

- 進一桌時寫 `jcmj_online_lock`（國、桌、時間），在牌桌期間定時更新時間
- 另一個分頁要加入任何一桌 → 鎖還新鮮（例如 30 秒內有更新）就擋下：「你已經在『某某桌』了」
- 離開牌桌就清鎖；分頁直接關掉的話，鎖過 30 秒自然失效
- 沒登入的人跨裝置認不出是同一個人，只能做到「同一個瀏覽器」
- **登入的人跨裝置也擋得到**：在 Firebase 記「這個帳號正在哪一桌」（`/players/{uid}/session`），另一台裝置要上桌時先檢查

## 七、國庫怎麼顯示（大家看得到彼此的國庫）

1. **房間的成員名單**：「本國・征服 N 國・國庫 X 兩」，低於 300 兩紅字
2. **一場結算**：每個人「國庫 前 → 後」，亡國的標「亡國」
3. **牌桌名牌**：只有國庫**低於 300 兩**時才出現紅色小標「⚠️ 國庫 180」，平常不佔位置
4. 畫面上方照樣是自己的國庫與彩池（同單機）

別人的國庫由他本人那台算好、跟著成員資料發出來；不能防作弊（朋友間玩，可以接受）。

## 八、不做的事

- **Apple ID 登入**：要付費加入 Apple 開發者計畫（每年 US$99）才能設定；等真的很多 iPhone 玩家不想用 Google 再加
- **單機進度上雲端**：這次只做連線的七國進度；單機的十格存檔照舊存瀏覽器
- 防作弊（進度由各自那台算，雲端的規則只擋「別人改你的」，擋不住自己改自己的）

## 九、Firebase

- 成員資料多帶「本國、征服地、國庫」的快照（房間名單、名牌要顯示）
- 群組底下的規則看起來**不需要改**（欄位沒有白名單，只限字串長度）；實作前再逐條確認
- **登入要新增規則**（第十一節的 `/players/{uid}`）：**先把規則內容給使用者看，同意了才部署**
- 舊的 `/camps`（一桌一段戰役的成員名單）用不到了：照「清掉重來」由 `tools/db-janitor.py` 清，清之前列給使用者看

## 十、舊資料

- 玩家瀏覽器裡的舊連線存檔（`jcmj_online_saves`）**清掉**：新版第一次打開時刪掉，並提示一次「連線改成七國進度，舊的連線存檔已清除」
- 「繼續之前的牌桌（連線存檔）」這一區拿掉

## 十一、登入（選用）

2026-10-16 使用者：「我在考慮要不要登入這件事，因為只記瀏覽器不太好」→ 決定補上。

### 玩家看到的樣子
- **不登入照樣能玩**（跟現在一樣，進度存瀏覽器）；想換裝置、怕進度不見的人再登入。第一次來玩的朋友不會被擋在登入畫面
- 登入方式：**Google**、**信箱連結**（輸入 email → 收信 → 點連結就登入，不用記密碼）
- **v1.75 改成 Email＋密碼**（2026-10-16 使用者 iPhone 實測：outlook.com 收不到信；點信裡的連結在 Safari 打開、不是全螢幕；
  Safari 跟加到主畫面的 App 儲存分開，Safari 登入了 App 還是沒登入 —— 「每次都要 send email 嗎？不太方便」）：
  第一次用就是註冊（密碼要打兩次），之後在哪台都直接登入；忘了密碼才寄重設信。
  防 Email 列舉開著，「沒這個帳號」跟「密碼錯」分不出來 → 再打一次：一樣＝註冊、不一樣＝重試。註冊時匿名身分升級（uid 不變）。
  信件連結：舊版頁面（輸入框不認密碼模式）照舊寄；已經寄出的連結照樣能登入。Firebase 的「電子郵件／密碼」本來就開著（信件連結掛在它底下）
- 登入一次之後那台裝置保持登入，換新裝置或登出過才要再登一次
- 大廳顯示「已登入：某某@gmail.com」與登出鈕；沒登入顯示「登入後換裝置也能接著打」

### 信箱連結怎麼跨裝置
身分就是 email，「密碼」是信箱本身：在任何一台輸入 email → 收信 → **在同一台**點連結 → 登入同一個帳號、看到同一份雲端進度。

### 技術
- Firebase Auth：Google（彈出視窗）＋ Email link（passwordless）。兩種都免費（每月 5 萬個活躍使用者內）
- **匿名升級**：Google 登入時把匿名身分**連結**到 Google 帳號，代號（uid）不變；那個 Google 帳號已經有人用過（例如在別台登入過）就直接換成那個帳號。
  ⚠️ **Email 不升級、一律直接登入**（v1.69 實作時改）：信裡的連結只能用一次，Email 已經有帳號時升級會失敗、連結也被用掉，退回去登入就變成「連結無效」；事先又查不到帳號在不在（新專案預設防 Email 列舉）。匿名身分丟掉沒關係——這台的七國進度在登入時合併上雲端，而且登入只在大廳做
- 雲端資料：`/players/{uid}/kingdoms/{國}`（第二節的格式）、`/players/{uid}/session`（第六節）、`/players/{uid}/fame`（連線功業簿）
- 規則：`/players/{uid}` 只有本人能讀寫（`auth.uid === $uid`）—— **新增規則，部署前要使用者同意**
- 授權網域要加 `allenkwl.github.io`（與 localhost）

### 兩台裝置都有進度時（合併）
例：手機沒登入打了秦國，電腦登入後也有秦國 → 同一國取**打過比較多場**的那一份，畫面上告訴玩家「秦國用了電腦上的進度（第 8 場）」。

### 要先實測的坑
- **iPhone 加到主畫面的遊戲**跟 Safari 是兩個分開的環境：在主畫面版輸入 email、在郵件 App 點連結，打開的是 Safari，登入到的是 Safari 那邊。
  Google 登入在主畫面版也可能被擋。要在 iPhone 實際試，可能的解法：在 Safari 登入後再重新加到主畫面
- GitHub Pages 的網域跟 Firebase 的登入網域不同，iPhone Safari 對「跳轉回來」的流程限制多 → 優先用彈出視窗；彈不出來時要有清楚的提示
- 信可能晚到或進垃圾信件匣：登入畫面要提醒

### 隱私
登入後 Firebase 會存玩家的 email。登入畫面寫一句：「只用來辨認是你、讓你換裝置也能接著打，不會寄別的信。」
