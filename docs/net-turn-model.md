# 線上版的回合模型：群主當裁判

> 定案 2026-09-23，同日實作宣告仲裁並實測通過。動第 16 項「牌局同步」前先讀完這份。
> 規則：**日本麻將（十三張）**，不是台灣十六張。

## 一、核心設計

**連線的任何時刻，都是群主裁定「該誰出手」。**

群主的程式跑完整的牌局狀態機（`flow.js`），但**不替任何人做決定**。
每一個決定 —— 打哪張、要不要自摸、要不要碰、要不要胡 —— 都由那一家的用戶端
用**自己的視角**做，再送給群主。群主只負責三件事：

1. 宣布現在輪到誰、在等誰
2. 收下動作，擋掉不合法的（不是你的回合、舊視窗的回覆、同一家回兩次）
3. 多家搶同一張牌時，照優先權裁決

各家用戶端只拿得到自己那一份：自己的手牌 ＋ 公開資訊（牌河、副露、剩幾張、輪到誰）。

> 草擬時曾寫「群主不跑別人的遊戲邏輯、不需要看手牌」。實作時改掉了：
> 群主的程式本來就知道所有牌（它發的牌，見第六節），讓它持有完整狀態，
> 逾時過水、換群主接手都變得很簡單，而**用戶端**看不到別人的牌這件事一點也沒少。

## 二、實際做法：每一個時刻由誰決定

| 時刻 | 群主做什麼 | 用戶端做什麼 |
|---|---|---|
| **開局** | 產生牌山、發牌；把每家 13 張寫進各自的私有節點；公開狀態寫進 `/states`；token 指給莊家 | 讀自己的節點，畫出手牌 |
| **輪到某家** | 從牌山摸一張，寫進**那一家**的私有節點；token 指給他 | 輪到的人：用自己的手牌算能不能自摸／暗槓，決定打哪張，送出 |
| **收到打牌** | 驗證（是不是輪到他、牌存在）；記進牌河；**開宣告視窗問另外三家** | — |
| **宣告視窗** | 等三家**都回齊**（不是等秒數） | 各自用自己的手牌算：沒東西 → **秒回「過」、不跳視窗**；能碰／能胡 → 跳視窗等真人按，回覆時附上「這張我本來胡不胡得了」 |
| **回齊了** | 丟進 `resolve()`：胡 > 碰槓 > 吃，同級近者優先。有人成立 → token 給他；沒人 → token 給下一家 | — |
| **能胡卻沒胡**（碰了、過了、逾時） | 設這一家的過水，到他下次摸牌為止 | — |
| **電腦座位** | 由群主代跑，但走**同一套**「自己算、自己報」（`C.selfResponse`） | — |
| **有人斷線** | `F.startSub`：由該國武將代打，廣播「主公斷線，現由某某代打」。電腦一旦替他出手，這一場就不記給他（`docs/campaign.md` 第五節） | 回來 → 群主 `F.endSub`，可以繼續打完 |
| **群主斷線** | `maybeReassignHost` 選出新群主；新群主讀回完整狀態接著當裁判 | — |

### 為什麼不會「過水」（錯過時機）

⚠️ **沒東西可宣告的那台，自己就知道。** 所以群主等的是「回齊」，不是一個固定秒數 ——
手慢的人不會錯過，因為根本沒在計時。逾時（`claimTimeoutMs`）只剩防斷線／防發呆，
可以放寬到 20 秒以上，正常情況永遠用不到。

### ⚠️ 不能「誰先舉手就跳給誰」

一定要收齊三家才裁決。照「先舉手先贏」的話，**手快的碰會蓋掉手慢的胡** —— 那是規則判錯。
`resolve()` 已經實作完整優先權（含多家同時榮和、三家和了流局），不要另寫一套。

## 三、兩個「過水」是不同的東西

| | 意思 | 處理 |
|---|---|---|
| 口語的過水 | 沒即時舉手 → 錯過機會 | 第二節「等回齊」解掉了 |
| 規則的過水（見逃振聽） | **能胡卻選擇碰、過、或逾時** → 到下次摸牌前不能胡 | 真規則，保留 |

規則的過水沒有它，玩家可以放過一張、再等下一家打同一張，白吃的（`rules-core.js:404`）。

- 用戶端回覆時附 `couldRon`（這張本來胡不胡得了）；**碰代替胡**也算過水
- **逾時的人**沒有回覆，由群主用完整狀態代算（`fillTimeouts(win, hand)`）——
  否則斷線或發呆反而變成一條不會過水的路
- 碰**不摸牌**，過水撐到下一次真的摸到牌；⚠️ 不要在 `applyMeld` 裡順手清掉
- 過水擋的是**所有和牌張**，不是只擋剛才那一張

## 四、手牌怎麼藏：狀態拆三層

| 節點 | 內容 | 讀 | 寫 |
|---|---|---|---|
| `/states/{群}` | 牌河、副露、輪到誰、剩幾張、宣告視窗 | 全體 | 群主 |
| `/hands/{群}/{uid}` | 那一家的手牌、過水旗標 | 本人、群主 | 群主 |
| `/secret/{群}` | 牌山本體 | 群主 | 群主 |

```
"hands": { "$g": { "$uid": {
  ".read":  "auth.uid === $uid || auth.uid === root.child('groups/'+$g+'/host').val()",
  ".write": "auth.uid === root.child('groups/'+$g+'/host').val()"
}}},
"secret": { "$g": {
  ".read":  "auth.uid === root.child('groups/'+$g+'/host').val()",
  ".write": "auth.uid === root.child('groups/'+$g+'/host').val()"
}}
```

- 群主要**寫得進**別人的節點才發得出牌（第一版草稿只准本人寫，那樣發牌走不動）
- 群主要**讀得到**別人的節點，換群主時新群主才接得回完整狀態
- 規則裡的 `host` 是**現任**群主 —— 換人之後權限自動跟著走，不用搬資料

> 草擬時打算只存 seed、由新群主重算牌山。改成直接存牌山本體：重算要 seed、莊家、
> 偏置發牌參數（`docs/biased-deal.md`）全部對得上，漏一個就發出不同的牌，
> 而且錯了不會報錯。多存 5KB 換掉一整類靜默錯誤，划算。

⚠️ **為什麼非拆成獨立路徑不可**：RTDB 的 `.read` 一旦在某節點給了，整棵子樹全開，
深層收不回來。規則只認路徑、不認欄位 —— 手牌留在 `/states` 裡就寫不出「這欄不給看」。

`/secret` 與 `hands` 都已在 `src/net.js` 的 `GROUP_NODES`（解散群組時清掉的清單）。
⚠️ 以後再多一棵資料樹，也要加進那份清單，不然會永遠留在資料庫裡。

### 廣播事件也要過濾

`flow.js` 的 events 是畫面層放動畫、網路層廣播用的。其中 `draw` 與 `rinshan`
**帶著摸到的那張牌** —— 照原樣廣播等於把每一張摸牌發給所有人，狀態拆得再乾淨也白費。
廣播前一律過 `F.eventsFor(events, 收件人座位)`：摸牌的本人拿到完整事件，
其餘三家只知道「某家摸了一張」。

暗槓不用過濾：日本規則的暗槓兩端蓋、中間兩張亮，**牌種公開**（`render.js`）。
⚠️ 哪天改台灣規則（暗槓整副蓋）的話，`kong_dark` 也要加進過濾。

## 五、實作狀態（2026-09-23）

**已完成（`src/claim-arbiter.js`、`src/flow.js`）：**

- 群主模式宣告視窗：`ctx.announce = true` 時，打牌後一律問另外三家，視窗不帶 `eligible`
- `C.selfResponse(hand, seat, win, choose)`：**用戶端要跑的那一段** —— 只讀自己的手牌，
  沒東西直接回 pass 不呼叫 `choose`（＝不跳視窗）
- `resolve()` 兩種模式共用：優先權只看「誰喊了什麼、離打牌者多遠」
- 群主只擋**用公開資訊驗得出來**的錯：吃只有下家、護送的牌不能鳴、搶槓只能胡、
  喊胡卻自報不能胡。驗不了的（手上到底有沒有那兩張）就信 —— 程式是我們的
- 逾時者的過水由群主代算
- `F.eventsFor(events, seat)`：廣播前過濾摸牌事件
- 單機完全不受影響（不傳 `announce` 就是原本的中央模式）

**實測（`test/net-turn.test.js`）：** 同一個 seed，中央模式與群主模式各打一次、逐事件比對。
用戶端拿到的別家手牌與牌山全換成**一碰就炸的假牌**。

- 完整版（`NET_FULL=1`）：166 場 664 局**逐事件一致**，沒有任何決策路徑碰到別家的牌；
  每回一家就模擬一次「群主斷線、新群主從 Firebase 讀回接手」，共 35,145 次，照樣一致
- 日常版約 8 秒，已在 `tools/run-tests.sh` 裡

**代價：** 宣告視窗從 763 次變成 4,794 次（日常版 16 場的數字，約 6 倍）。
多出來的全是「三家秒回 pass」—— 群主不知道誰能鳴，只能每張都問。
電腦座位由群主代答不走網路；真人座位每次打牌多一個來回，估計 0.2～0.3 秒。
實體麻將打出一張牌本來也有這個停頓。

## 六、群主的程式知道所有人的牌

誠實記一筆：群主發的牌，所以它的程式知道每家的每一張牌。**無伺服器沒辦法避免** ——
發牌一定發生在某台機器上。「程式知道」不等於「人知道」：那些牌在記憶體裡，畫面不顯示。
前提是程式是我們自己的、朋友之間玩（2026-09-23 確認）。
