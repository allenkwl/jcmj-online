# 戰役結構 —— 四人版怎麼推行下去

## 為什麼需要這份文件

選國畫面原本是：**① 選本國　② 選征服目標　③ 對手（自動抽籤）**。

玩家反應是「搞不清楚對手被打敗，但是被征服的卻和被打敗的無關」——
而程式自己的註解就寫著答案：

```js
// 對手是自動抽的 —— 讓玩家選沒有意義（征服判定與對手是誰無關，見 PLAN）
```

你在牌桌上打敗魏、齊、趙，地圖上卻拿走楚。兩件事被刻意脫鉤，玩家當然對不起來。
這份文件把整條線重新接上。

## 一、核心模型：土地是「個人收藏」

這是舊版就有的結構，四人版只是每人各帶一份進來：

```js
// 舊版
G.opps = KINGDOMS.filter(k => k.id !== G.playerK.id);   // 其餘六國
G.conquered = [];                                        // 自己打下來的
if (save.conquered.length > 5) → 統一天下
```

所以**四個玩家手上的國本來就會重複**，那不是 bug 是常態 ——
可能兩人都擁有六國，最後一戰決定誰統一天下。大廳要看得到各人手上有哪些國。

| 概念 | 意義 | 會不會變 |
|---|---|---|
| **本國** | 你的身分，決定技能 | 不變（除非「重整旗鼓」時自己換） |
| **征服地** | 打贏累積來的收藏 | **只增不減** |
| **統一天下** | 本國 + 征服六國 = 七國 | 戰役結束 |

### 推論：不鎖國

一度決定「大廳先搶先贏、選走的國別人不能選」，理由是我們只有君王大頭貼，
兩個齊國在畫面上分不出來。**這個決定作廢。**

在個人收藏的模型下，國家不代表「誰擁有地圖上的哪一塊」，
它只是**技能來源＋頭像**；身分由玩家名字承擔。所以：

- 名牌顯示**玩家名字**，不是國名也不是君主名
- 國家降級成小標籤＋描邊色
- 單機的三家 AI 就叫君主名（你打的是各國君主），線上換成玩家暱稱 ——
  兩種模式各自自洽，也不需要武將立繪

技能衝突早就解決過了（一律作用在自己，見 `skill-conflicts.md` 第六節），
所以同國純粹是辨識問題，而辨識問題被名字解掉了。

## 二、一場四局的結算　★定案

| 名次 | 土地 |
|---|---|
| 第一名 | **+1** |
| 第二名 | **+1** |
| 第三名 | **+1** |
| 第四名 | **0** |

- **只進不退**：沒有任何人會被扣地
- **一場最多拿一國**：七國總共才七個，一場拿兩國怪怪的
- **名次**：用 `scoring.js` 的 `standings()`（分高者前，同分時莊家順位在前）

### 征服的是哪一國

**你征服的是「排在你後面的人」當中的一國。**

| 名次 | 後面有誰 | 征服 |
|---|---|---|
| 第一名 | 二、三、四 | 從中取一國 |
| 第二名 | 三、四 | 從中取一國 |
| 第三名 | 四 | 第四名那一國 |
| 第四名 | **沒有人** | **0** |

這讓 `+1/+1/+1/0` 從一條數值規則變成一句話講得通的規則：
**「打敗誰就拿誰的地，墊底的人沒打敗任何人」**——
第四名拿不到地不再需要解釋。

取不到時（那一國你已經征服過了）才退回「從你所有未征服的國裡隨機取」。
單機因為對手優先抽未征服國，退路很少用到；線上則常用。

## 三、追趕機制與「重整旗鼓」　★定案

**觸發**：

| 你的處境 | 觸發條件 |
|---|---|
| 手上只有本國（征服數 0） | **墊底一次** |
| 已有征服地 | **連續兩場墊底** |

**效果**：

1. **追趕機制** —— 提高該玩家的特殊牌型機率，不再墊底就關掉
2. **重整旗鼓** —— 征服數為 0 時，同時提供「要不要換一國」。
   這時你本來就沒有東西可以失去，所以它是**免費換國的機會**，不是懲罰

越沒有進度的人保護來得越快。而且把換國跟一個好處綁在一起，
它讀起來是「遊戲在幫你」而不是「你失敗了」——
所以措辭用**重整旗鼓**，不要用 Game over。

**這是手感機制，不是算術機制。** 實測它對戰役總長度幾乎沒有影響
（超弱玩家 63 手 → 62 手），價值在於新手最脆弱的那一兩場有保護，
觸發頻率每戰役 0.2～1.3 次。**第二節的數值必須自己就是安全的，不能指望它來補。**

**作弊疑慮**：故意連輸換加持，代價是那幾場沒拿到地、收益只有一場，不划算，自我限制。

**包裝**：講成天命（「連年征戰，天命垂憐」），不要講成系統放水。

## 四、為什麼是這組數字

`tools/sim-campaign.py`（每案跑 20000 次戰役）：

| 玩家程度 | ★ +1/+1/+1/0 | +2/+1/+1/0 | 只有第一名 +1 | 第一名+1、第四名−1 |
|---|---:|---:|---:|---:|
| 高手 墊底15% | **28 手** | 20 手 | 60 手 | — |
| 普通 墊底25% | **32 手** | 25 手 | 96 手 | 335 手 |
| 弱 墊底40% | **40 手** | 35 手 | 240 手 | — |
| 很弱 墊底55% | **53 手** | 49 手 | 479 手 | — |
| 超弱 墊底70% | **80 手** | 76 手 | **1199 手** | — |

舊版是一對一、贏一手牌就征服一國、輸了不倒退，全程約 **12 手牌**。

三件事是這份設計的依據：

1. **「只有第一名前進」照顧不到弱玩家。** 前進速度 = 拿第一的機率，
   而那正是弱玩家最缺的東西。墊底 70% 的人要 1199 手（約 30 小時），等於永遠到不了。
2. **「第四名扣一國」更糟。** 期望淨增長歸零，戰役變成隨機漫步；
   從 1 國走到 7 國中途不歸零的機率只有 1/7，實測 335 手、平均亡國六次。
   問題不在「有沒有退」，在於獎勵沒有攤開給名次。
3. **前三名都 +1 之後，高手 28 手、超弱 80 手，差距只有 2.9 倍。**
   有實力區別，但沒有人走不完。

設計原則（玩家原話）：
**「這是要好玩的遊戲，不該有人失望」**、
**「這個遊戲就是要大家都有機會拿到特殊牌，讓不會打麻將的人也可以玩得很開心」**。

## 五、單機版 vs 線上版

| | 單機版 | 線上版（階段三） |
|---|---|---|
| **選國畫面** | ① 選本國 ② 對手 ③ 難度 | **完全一樣** |
| **難度的意義** | 三家 AI 的強度 | **遞補／接手 AI 的強度**，由群主設定 |
| 對手 | 3 家 AI | 真人，不足由 AI 補位 |
| 對手怎麼抽 | **優先抽你還沒征服的國** | 別的玩家，抽不到就配 AI |
| 征服哪一國 | 排你後面的人當中，你還沒征服的 | 同左；取不到就從未征服的六國隨機 |
| 對手的戰役進度 | 無，AI 只是關卡 | 每人各自一份 |
| 鎖國 | 不需要（發四個不同的） | **不鎖**，可以選同一國 |
| 名牌 | 君主名 | 玩家暱稱（AI 接手時標示「代打中」） |
| 存檔 | localStorage | Firebase |
| 特殊牌型機率 | 高（70%） | 低（40%） |

線上也選難度之後，**兩種模式的選國畫面完全相同**，少一套 UI 也少一條分支。
極端情況（三人都斷線）就退化成單機，而那時難度已經選好了。

### AI 的技能不成長

**AI 的 `conquered` 永遠是 0**（`growthTier` = 0），不隨難度變動。

一度想過「高手 AI 給等價 4 國、技能也更強」，那是錯的：
難度會同時往**打法**和**技能**兩個方向加壓，對弱玩家雙重不利，
跟「不該有人失望」衝突。難度只調 AI 的打法（`aiLevel` 1/2/3）就夠了。

固定在 0 還有一個好處：玩家隨征服數成長、AI 不會，
所以**戰役越到後面，玩家的技能越明顯強過對手** —— 那正是成長感該有的形狀。

`conquered` 是每個座位各自帶的（`flow.js:161`），所以 AI 座位填 0 即可。

### 斷線（沿用小球貓電鐵）

`~/Documents/DILA/小球貓電鐵/game-web/src/net-v1.22.js`：

```js
// 換電腦接手時**不刪掉**認領，只加一個 away 標記。
// 刪掉的話那個座位就再也不記得原本是誰的，人回來時「認領對得上」永遠不成立，
// 等於一旦被電腦接手就再也回不來。
```

| 機制 | 作法 |
|---|---|
| 斷線偵測 | `onDisconnect` 自動清節點 + 存活探測 |
| 接手 | 暫停 → **群主**決定要不要讓電腦接手 |
| 保留座位 | 座位加 `away` 標記而不是刪認領，人回來清掉就接回去 |
| 群主也斷線 | `maybeReassignHost` 用 transaction 換人 |

**接手用的機器已經有了** —— 自動打牌（`mj4.html` 的 `autoStep()`）就是同一套。
差別只在自動打牌僅於聽牌時接手（沒聽牌時代替玩家決定做什麼牌是不對的），
斷線接手要全程接，直接用 `AI.chooseDiscard`。

~~AI 代打那一場的土地照算。~~ **（2026-09-23 改掉）**

**電腦替他出過手，那一場的戰果就不記給他 —— 統一天下要靠自己。**

- 斷線後、電腦**真的出手之前**回來：沒事，照算
- 電腦替他打了牌，或替他決定要不要鳴（光是自動回 pass 不算）：這一場記為代打
- 回來之後可以繼續打完，但這一場已經不記了；回來時畫面會明講
- 別家照常記。代打座位仍然占一個名次，別家征服誰照完整排名算
- 聽牌後自己按的「交給系統打」**不算**代打：那是玩家自己的選擇，而且只是摸切
- 畫面：「【齊國】主公斷線，現由田忌代打」，名牌換成武將、主公像轉灰。
  武將名單在 `src/kingdoms.js` 的 `general`

實作：`match.seats[i].sub`（現在誰在代打，同步給所有人）、
`match.seats[i].subbed`（這一場電腦出過手，不會清掉）、`CP.creditable(match, seat)`。
群主偵測到斷線時呼叫 `F.startSub`，人回來呼叫 `F.endSub`。

⚠️ 副作用：快輸的時候故意斷線，這一場就不記 —— 包括不會墊底。
朋友之間玩不處理（2026-09-23 確認不考慮作弊）。

接手座位的技能等級沿用**該玩家自己的**征服數，因為那還是他的國。
